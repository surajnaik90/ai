# Understanding foundational models

## Training data

1. Data for training is available at **https://commoncrawl.org/** by non-profit org.   
   OpenAI GPT-3 & Gemini used that Common Crawl data for training their models.    
   Before using we need to clean data for language, quality, safety etc.   
2. Google provides **Colossal Clean Crawled Corpus (C4) dataset** for training the model.   

## Model architecture

1. **seq2seq architecture**   

    a. Introduced in 2014. Google used it in Google Translate in 2016.   
    b. Components:   
       * Encoder which processes input tokens sequentially and generates a hidden state.
       * Decoder which uses the hidden state and generates the output tokens sequentially.

    Problems:
    * Output tokens uses only the hidden state to generate responses. It's like reading the   
      summary of the book to generate answers.   
    * Since it is a sequential processing, the model takes time process large number of tokens.   


2. **Transformer architecture**   

    a. It addressed both the problems of seq2seq architecture with the **attention mechanism**   
    b. It allows the model to weigh the importance of different input tokens when generating each output token.   


## Post training

It is about making the pre-trained model to get into conversation mode rather than completion.
Also, to align with human preferences.    

There are 2 steps to it:   

1. **Supervised finetuning (SFT)**   
   a. Pre-trained models are usually based on completions. SFT makes it conversational.   
   b. Labelers (humans) create a (prompt, response) pair to finetune the model.

2. **Preferential finetuning**     
   a. Align with human preferences. Do not generate harmful context, comment against any race, reigion etc.
   b. Techniques used are:
      i.  Reinforcement Learning Human Feedback (RLHF)
          Reward model: In this 2 outputs are compared to pick the best ones.
      ii. Reinforcement Learning AI Feednack (RLAIF)


## Sampling

For a given input, neural network produces a list of possible outcomes. This happens for each   
token of the input. The possible outcomes have probabilities associated with them.    
Now the model can pick the output token based on the highest probability associated with it.

The outcome token is called logits (vectors). 

### Temperature

It's a constant used to tweak the model behaviour. 

Higher temperature will burn out the highest probabilities. There by giving importance to    
lower probabilities. This will make the model creative and not always produce the same tokens with     
highest probabilities.    

Lower temperature will make the model's response consistent. Always outputs the tokens with highest    
probabilities.

Probabilities associated with the models are called **LogProbs**

### Sampling strategies

**top-k**:

For a language model with large vocabulary size, there could be large no of logits generated by    
transformer model. This would make compute intensive while computing softmax.    
So, the top k logits with good scores are considered.

### Language model performance metrics   

1. **Entropy**: How much info a token holds?    
2. **Cross-entropy**: How difficult it is predict a next token?   
3. **Perplexity**: The amount of uncertainity in predicting the next token?
